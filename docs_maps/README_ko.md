# 챕터 지도 설계도 (사장님 2026-10-24)

> 사장님: 「전체 챕터 및 지도·아이템·인물 배치 장소 그려라. 챕터별 크기가 어마어마하겠지? 작게 하면 재미없으니까. 지도만 그려 주면 그록이 배경·몬스터 등 필요한 그림은 그려 준다.」

우리가 하는 일은 **지도 설계도**를 만드는 것이다. 어디에 무엇이 있는지를 정한다. 예쁜 그림은 그록이 그린다.
기준은 정본 하나다: `docs_story/MASTER_PLAN_정본_20261024_ko.md` (0절 = 사장님 확정 사항이 맨 우선) + `MASTER_PLAN_아이템배치_20261024_ko.md`.

## 한 챕터에 내는 것 (4개)
1. `chN_map.json`: 지도 데이터. 아래 형식을 따른다. 그림은 여기서 저절로 나온다.
2. `chN_overview.png`: `python3 tools/mapplan/draw.py docs_maps/chN/chN_map.json` 로 뽑은 전체 지도.
3. `chN_zone_<구역>.png`: 큰 구역마다 확대 그림. `--zone <구역id>` 를 붙여 뽑는다.
4. `chN_spec_ko.md`: 설명서. 아래 5개 절을 쓴다.
   - (1) 한 줄 소개와 분위기
   - (2) 구역 표: 이름·크기·지나가는 시간·몹·분위기
   - (3) 동선: 처음 길 / 지름길 / 다시 찾아오는 길(백트래킹)
   - (4) 정본 대조표: 정본에 나온 모든 인물·아이템·몹·보스가 지도 몇 번에 있는지. 빠진 것이 0개여야 한다.
   - (5) **그록에게 부탁할 그림 목록**: 배경 타일·큰 소품·몹·NPC·보스. 이름·크기(타일)·모습을 한 줄씩 쓴다.

## 크기 기준 (크게! 그래도 비면 안 됨)
- 1타일은 16px이다. 주인공은 1초에 약 5타일을 달린다.
- **한 챕터 전체**는 가로·세로 **400~800타일**이다. 끝에서 끝까지 달리면 80~160초가 걸린다. 지금 게임의 펠트 마을은 59×35밖에 안 된다. 그보다 10배 넘게 크게 만든다.
- **한 구역은 260×260타일까지**다. 게임에 실을 때 구역 하나가 맵 파일 하나가 되기 때문이다. 더 크면 둘로 나누고 `links` 로 잇는다.
- 던전의 층(1층·지하 1층·지하 2층)은 각각 따로 된 구역이다. 같은 그림 안에 옆으로 나란히 놓는다.
- **비면 재미없다**: 들판 구역은 50×50타일(달리기 10초)마다 몹 무리를 1개 이상 둔다. `--check` 가 검사한다.
- 몹 배치는 게임 핵심 규칙을 따른다. 빠르게 달려 붙어 베는 게임이다. 몹은 주인공을 겨누고, 공격 뒤에는 빈틈이 있고, 멀리 도망가지 않는다. 그래서 무리 사이가 너무 멀면 안 된다.
- 쉼터(모닥불, `save`)는 구역마다 1개 이상 두고, 보스 문 앞에는 반드시 둔다.
- 지름길(`shortcut`)은 챕터마다 2개 이상 둔다. 처음에는 잠겨 있고, 안쪽에서 열면 돌아오는 길이 짧아진다.
- 아이들(토비·펠릭스·이안)이 있는 곳에는 몹을 두지 않는다 (아동 절대 보호).

## `chN_map.json` 형식
```json
{
  "chapter": "ch1", "title": "잿빛 들판 & 폐공방", "w": 600, "h": 420,
  "zones":  [{"id":"felt", "name":"펠트 마을", "kind":"town", "x":250, "y":300, "w":120, "h":90, "note":"생존자 거점"}],
  "areas":  [{"kind":"cliff", "poly":[[x,y],[x,y],[x,y]]}],
  "paths":  [{"kind":"road", "w":3, "pts":[[x,y],[x,y]]}],
  "links":  [{"from":"felt", "to":"field", "kind":"gate", "at":[x,y], "label":"북문"}],
  "markers":[{"type":"npc", "name":"루카", "zone":"felt", "x":300, "y":340, "ref":"정본 6장 1장-1)", "note":"모닥불"}],
  "grok":   [{"kind":"bg", "name":"잿빛 들판 바닥", "size":"타일 16px 세트", "desc":"재가 눈처럼 쌓인 땅"}]
}
```
- 좌표는 전부 **챕터 전체 기준 타일 좌표**다 (0,0 = 왼쪽 위).
- `zones.kind`: town / field / dungeon / boss / interior / hidden / sky
- `areas.kind`: water / poison / mercury / cliff / forest / ruin / ash / fire / web / wall / pit / building / grave / gear / books / void
- `paths.kind`: road / river / wall / cliff / bridge / corridor / sewer / rail
- `links.kind`: gate / door / stairs / lift / shortcut / secret / oneway. 다른 챕터로 가는 길은 `"to":"ch2"` 로 쓴다.
- `markers.type`: start / save / npc / shop / item / chest / mob / elite / hidden_elite / midboss / boss / quest / landmark / shortcut / trap
  - mob은 `"note":"껍데기 4"` 처럼 무리의 몹 종류와 수를 적는다.
  - item·chest는 `ref` 에 정본 아이템 이름을 그대로 쓴다.

## 순서
1. 정본에서 그 챕터의 인물·아이템·몹·보스를 모두 뽑아 목록을 만든다.
2. 구역을 나누고 크기를 정한다.
3. JSON을 쓴다. `--check` 로 경고가 0개가 될 때까지 고친다.
4. 그림을 뽑는다 (전체 1장 + 구역별).
5. spec을 쓴다. 정본 대조표에서 빠진 것이 0개인지 본다.
6. 자기 브랜치에 커밋하고 push한다. 게임 코드는 건드리지 않는다. 팀장에게 overview 그림 경로와 숫자(크기·몹 무리 수·쉼터 수·지름길 수)를 보고한다.

정본에 없는 것을 지어내지 않는다. 정본에 위치가 정해져 있지 않은 것(예: 몹 무리 위치, 쉼터 자리)만 우리가 정하고, spec에 「팀 제안」이라고 적는다.
