# 0. 이 교본 쓰는 법
- 회의가 끝나면 **결론을 이 교본의 맞는 목차에** 적는다. 채팅에만 두지 않는다 (CLAUDE.md 「회의」, 사장님 10-25).
- 한 줄 = 결정 하나. 줄마다 **날짜(MM-DD) · 누가 · 근거(파일 경로 또는 브랜치@커밋)** 를 붙인다.
- 어디에 적나
  - 모션(그리기·고치기·크기·게임 연결) → 모션 교과서
  - 몬스터·보스 → 몬스터 교본
  - 그 밖(일하는 규칙·지도·경관·UI·효과·스토리·그록 부탁) → 이 교본
- 사장님 말씀은 「」 안에 **그대로** 옮긴다. 사장님 말씀이 가장 높다. 나중 말씀이 먼저 말씀을 이긴다.
- **최신만 남긴다**: 새 결론이 옛 결론을 바꾸면 옛 줄은 지우고, 새 줄에 「(MM-DD 바뀜)」을 적는다. 옛 내용은 git 기록에서 찾는다.
- 아직 정해지지 않은 것은 「미정」이라고 적고, 맨 끝 「부록. 미정·확인할 것」에도 적는다.
- 회의를 할 때마다 「10. 회의 기록 목록」에 한 줄을 더한다.
- 쉬운 한국어로 쓴다. 숫자는 그대로 적는다. 비밀 키는 절대 적지 않는다.

# 1. 일하는 규칙

## 1-0. 플랫폼 = PC (사장님 10-25)
- 사장님 「이거 피씨용 게임이야, 휴대폰은 테스트 할때만」 → 화면·조작·성능 기준은 PC(키보드·마우스·패드, 16:9, 1080p). 폰은 시험용. 이전에 폰을 기준으로 정한 숫자(전망 줌 최저 0.7, 폰 세로 안내, 「전투 중 — 저장 불가」 폰 자리, 폰 프레임 예산 8ms 등)는 PC 기준으로 다시 본다. 결과 영상은 PC 가로로 찍어 MP4로.

## 1-1. 사장님께 말할 때
- 초등학생도 알아듣게 쉬운 말로. 어려운 낱말은 안 쓰거나 바로 풀어 준다 (사장님 10-22, `CLAUDE.md`).
- 채팅은 진행 상황까지 **무조건 한글** (사장님 10-22). 결과는 MP4/이미지로 (폰에서 GIF 안 됨).
- 더 좋은 방법이 있으면 늘 추천한다. 한 줄로, 왜 좋은지 (10-22).
- **유의미한 변화가 있을 때만 묻는다** (10-23). 사장님 10-23 「유의미한 결과가 있을때만 보고해」.
- 사장님이 「1시간 동안 명령 없어도 알아서」라고 하면 묻지 않고 계속 연구·개선한다 (10-24 「보고서 팀원들과 공유하고 회의 충분히 하고 1시간 동안 명령 없어도 알아서 개선점 찾고 변경해」).
- 사장님이 「정지해」라고 하면 모든 일을 멈추고, 하던 것만 적어 둔다 (10-25, 모션 담당 보고).

## 1-2. 직원 → 팀장 보고 방식 (10-24부터 굳어진 모양)
- 보고에 꼭 넣는 것: **브랜치 이름 + 커밋**, 무엇이 바뀌었나, **숫자(전 → 후)**, **영상 경로**, **쓴 크레딧**, 시험 결과(`test_openworld 17/17`, 페이지 오류 0).
- 못 한 것·나빠진 것도 정직하게 적는다 (예: 모션 「나빠진/남은 것(정직하게)」).
- 지어내지 않는다. 자료를 못 찾으면 「못 찾음」이라고 쓰고 출처를 적는다 (몬스터·검흔 담당 얼굴·팔 연구).
- 정본에 없는 것은 「팀 제안」이라고 표시한다 (`docs_maps/README_ko.md`).

## 1-3. 브랜치·합치기·게임 반영
- 게임(main) 반영은 **사장님 허락(「넣어」) 뒤에만**, 늘 브랜치 → PR (`CLAUDE.md`). 라이브 `/town/` 은 건드리지 않는다.
- **force push 금지.** 다시 올릴 때는 **새 이름**으로 올린다 (예: `claude/map-ch6-v2`, `-v3`, `-v4`). 10-24 효과 담당이 force-with-lease 실수 → 「앞으로는 새 이름으로」.
- 통합 브랜치 = `claude/linette-8dir` (팀장). 직원은 자기 브랜치에 올리고, 빨리감기(fast-forward)로 합칠 수 있게 최신 위에 올린다.
- 모션연구방은 `claude/motion-lab` 하나만 push 한다 (10-24 모션 담당).
- **같은 코드 줄은 한 사람만 합친다** (10-24 효과·모션 합의):
  - 검흔·칼 코드(`gk*`, `heroBlade`) = 효과 담당 혼자.
  - 모션 담당 = 그림·손 좌표·몸 반동만. 바꾸기 전에 효과 담당과 먼저 맞춘다.
  - 이야기 그림 줄(`drawCg` / `SCENE_FX` / `drawSceneFx`)은 효과 담당이 건드리지 않는다.
- 사장님이 직원 방에 직접 지시한 일은 그 방이 하고, 팀장에게 알린다. 겹치면 팀장이 하나로 정한다 (10-24 보스 UI 「맡아」 건).
- 한 줄 코드 뒤에 `//` 주석을 붙이지 않는다. 두 번이나 뒤 코드를 삼켰다: `gx0 is not defined`(10-24, motion-lab 2f0625a6) / 카메라 줌이 안 먹음(95da13a1부터, 10-24 vista-fx에서 발견). → `/* */` 로 닫는다.

## 2-1. 한 줄 핵심 (사장님 10-23, `CLAUDE.md`)
- 빠르게 달리며 검기로 스피드 있게 공격 → 몹 공격을 맞거나 저스트 회피로 피하며 필살기 게이지를 쌓아 → 큰 스킬을 맞춘다.

- 사장님 10-24 「너희들은 모두 전체 챕터 및 지도 아이템 인물 배치장소 그려라. 챕터별 크기가 어마 어마 하겠지? 작게하면 재미 없으니까. 지도만 그려주면 그록이 배경 및 몬스터 등 필요한 이미지는 그려주니까」.

## 4-5. 1차 경관 연구 (10-24, `docs_maps/LANDSCAPE_RESEARCH_ko.md`)
- 사장님 10-24 「인트로부터 1챕터부터 가자. 근데 나무랑 돌만 놓기 단조로우니 엘든링처럼 자연경관 웅장하게 배치 할수 있도록 지도에 경관 위치 배경 팀원들과 회의해」.
- 성 안이라 「자연」 = **무너진 도시가 자연이 된 모습** (산 → 무너진 성벽·탑, 강 → 수도교·잿가루 폭포, 숲 → 석화 나무, 골짜기 → 꺼진 지반, 호수 → 검은 물에 가라앉은 종탑).
- 지도 형식에 `scenery`(경관)·`vistas`(전망 자리) 추가.
- 1장 경관 9개(외성벽·내성벽과 왕성 탑·석화 거대 나무·무너진 수도교·꺼진 지반·붉은 실·쓰러진 거인 기사상·검은 호수·옛 성문 아치) + 한 줄 사연(정본/팀 제안 구분).
- **다음 표지물 사슬**: 무덤가 → 정문 밖 거인상 → 거인상 위 → 수도교 → 폐공방 → 보스 뒤 석화 나무 절벽에서 2장.
- 회의 반영(6절): 경관 둘레·물·높은 길 위는 몹 비움, 첫 언덕 반지름 40은 몹 0, 경관을 싸움 무대로(수도교 위·거인 등·구덩이 가장자리·호수 둘레·석화 나무 기습). 거인 손바닥 첫 모닥불, 루카 모닥불 연기 기둥, 가라앉은 종탑 = 펠트 종탑 종소리 복선.
- 인트로 대본 5줄 (무덤가 → 첫 언덕): `LANDSCAPE_RESEARCH_ko.md` 6절 끝.

## 4-7. 2차 연구: 2D로 웅장하게 짓는 법 + 맵 종류 7개 (10-25, `docs_maps/MAP_BUILD_RESEARCH_ko.md`)
- 사장님 10-25 「지도 및 맵 구현 엘든링처럼 2D로 웅장하게. 각종 맵구성 어떻게 할지도 연구 회의해」. 참석: 팀장·UI·효과·모션·스토리·몬스터, 크레딧 0.
- **한 줄 결론**: 웅장함은 줌을 크게 빼서가 아니라 ① 먼 배경 시차 ② 화면에 다 안 들어오는 거대한 것 ③ 높이 3층 ④ 앞 가림 ⑤ 맵마다 다른 빛과 색에서 나온다.
- 그리는 층 8개(먼 배경·아래층·바닥·그림자·소품캐릭터·앞 가림·효과·화면 색) → 5-9.
- **높이 3층** (모션): 낮은 곳 / 땅 / 높은 길. 계단·경사로·회피대시 틈 넘기(틈은 2칸 이하)는 새 모션 없이. 사다리만 새로(약 18크레딧). 턱 매달리기는 쓰지 않음. **층이 바뀌어도 주인공 크기 그대로** (사장님 지적). 시험판 `?height=1` (motion-lab c2b61c82).
- **크기 대비** (주인공 키 34px): 옆 기준물 2~3배 / 보통 소품 3~4배 / 큰 문·석상·성벽 6~10배 / 먼 거대 구조물 20배 이상, 시차 0.2~0.4, 화면에 다 안 들어오게 자름.
- 맵 종류 7개: ① 들판 ② 거점 마을 ③ 성채형 던전 ④ 작은 던전 ⑤ 보스방 ⑥ 잇는 길 ⑦ 숨은 곳. 종류마다 카메라(5-4)·싸움 공간(8-3)·이야기(4-8)·분위기(6-4)가 정해짐.
- 지도 데이터에 더할 것: 구역 `kind`(①~⑦), `level`(0/1/2), 소품 `occludeY`(가림선) + 앞/뒤 그림, 효과 `mood`, 그록 바닥 32타일 조각 이름표.
- 만드는 순서 8단계(`?perf=1` → 그록 바닥 조각 → 먼 배경 → 앞 가림 → 높이 3층 → 맵 종류별 카메라 → mood → 점검 규칙). 모두 사장님 허락 뒤 브랜치에서.

## 4-8. 이야기를 풍경으로 (스토리, 10-25, 근거 정본 3·6·7절, 정본 밖은 팀 제안)
- **아이템 설명 한 줄 = 그 아이템이 놓인 풍경 한 장면.** 쪽지·벽글은 3줄을 넘기지 않는다.
- 들판: 유해의 쓰러진 방향이 사연 / 거대 구조물엔 「왜 무너졌나」 한 줄 / 싸움 흔적이 다음 목적지를 가리킴.
- 거점 마을: 사람이 바뀌면 풍경도 바뀜(루카 죽으면 연기 끊김, 가스 떠나면 빈 초소에 의수) / 아이가 있는 곳은 따뜻한 빛·빨랫줄.
- 성채형 던전 **6박자**: ① 입구 예고(무엇을) ② 위층 일상 ③ 중간 반전(왜) ④ 깊은 곳의 대가 ⑤ 보스 앞 마지막 조각 ⑥ 보스 → 방 변화 → 보상 설명이 마지막 줄. (폐공방 예: 왕실 천·주문 장부 → 재봉틀 → 꿰매진 인형 → 빈 고치·붉은 목도리 → 마지막 기록 → 붉은 마지막 기록 실타래)
- 작은 던전: 한 사연에 보상 하나, 막다른 길 끝엔 꼭 이야기.
- 보스방: 집착 물건이 한가운데(베틀·성문·옥좌), 먼저 온 희생자 흔적, 처치 뒤 방이 바뀜.
- 잇는 길: 다음 장이 멀리 보임, 안내판 대신 유해·피 자국. 숨은 곳: 앞 구역에 단서, 보상은 가장 조용하고 슬픈 사연.
- 1~8장 성채형 던전·보스방 한 줄 사연 → `MAP_BUILD_RESEARCH_ko.md` 5-3.
