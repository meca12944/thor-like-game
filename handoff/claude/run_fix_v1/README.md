# 달리기 프레임 어긋남 진단 + 수정안 (오른쪽 달리기, 그림 수정 없음)

대상: 샌드박스(`test128/sandbox/assets/hero_sbx.json`)와 게임(`test128/assets/anim/hero8.json`)의 `run_right` / `run_left`. 둘 다 같은 원본(12프레임 × 3틱 = 36틱)을 쓴다.

## 문제 (디딘 발의 위치를 프레임마다 측정)
- 발 접지 x (앵커 기준, px): 10, -2.5, -16.5 | 22.5, 19.5, 21, 6.5, -9, -23.5, -35.5 | 29.5, 34
- 디딘 발이 3프레임 동안 제자리에 있다가, 다음엔 프레임당 14px씩 뒤로 간다. 마지막 → 첫 프레임에서 24px 튄다.
- 한 바퀴 동안 발은 뒤로 104px 가는데 캐릭터는 2.2px/틱 × 36틱 = 79px만 간다 → 발이 땅에서 미끄러진다.
- 미끄러짐 합(디딘 발이 땅에 붙어 있어야 하는 구간의 어긋남): **83.6px**

## 수정안 (그림은 그대로, 순서와 시간만)
- 순서: 4·5번(c325, c133)과 11·12번(c328, c329)을 서로 바꾼다 (둘 다 착지 직후 프레임이 거꾸로 들어가 있었다).
- 프레임별 틱: 디딘 발이 다음 프레임까지 움직이는 거리 ÷ 2.2 → `[6,6,3,1,1,6,7,7,5,3,2,7]` (한 바퀴 54틱).
- 미끄러짐 합: **9.3px** (마지막 착지 한 곳 4px만 남음).
- 대가: 한 바퀴가 36틱 → 54틱이라 다리 회전이 1.5배 느려진다. 다리 회전을 그대로 두려면 달리기 속도를 2.2 → 3.3px/틱으로 올리면 된다(같은 비율).
- `run_fix.json`: 새 순서와 틱. `run_compare.mp4`: 위 = 지금, 아래 = 수정안 (바닥 눈금이 캐릭터 속도로 흐름). `run_fixed_strip.png`: 수정안 12프레임.

## 다른 방향
`run_current_3dirs.png`: 위부터 오른쪽, 오른쪽 위 대각, 오른쪽 아래 대각. 대각 위는 칼이 앞에서 뒤로 넘어가며 고리가 안 맞고, 대각 아래는 발이 최대 18px 떠서 몸이 크게 튄다. 이 둘은 시간 조정으로는 못 고친다(다시 생성해야 함).
