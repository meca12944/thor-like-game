# 아트 스타일 샘플 (전체 변환 아님)

목표: 배경 = **매끈한 손그림(페인팅) + 정면 탑다운(직교)**, 캐릭터 = **지금보다 2배 섬세한 픽셀아트**, 60 fps 유지.
라이브 게임 파일은 건드리지 않음. 이 폴더만으로 동작하는 독립 테스트 페이지.

## 방식
- **배경**: 화면 해상도로 직접 그림 (부드러운 보간, 픽셀 격자 없음). 월드 좌표는 지금과 같은 1280×720 (마을 A 와 같은 한 화면 지도).
- **캐릭터**: 논리 해상도 **768×432** (지금 384×216 의 2배, 타일 32px) 버퍼에 정수 좌표로 그린 뒤 *sharp-bilinear* 로 화면에 올림
  (최근접으로 다음 정수배까지 키운 뒤 한 번만 부드럽게 줄임 → 1920×1080 = 2.5배 같은 비정수배에서도 픽셀 폭이 고르게 보임).
- 그림자는 화면 해상도의 부드러운 타원 → 페인팅 위에 자연스럽게 앉음.
- 주인공 56px (지금 28px), 성인 여성 68px (7.9 등신, 다리 0.50 — 생성 원본은 6.7 등신 / 0.45 라서 머리 축소 + 다리 늘림 보정).

## 측정 (headless Chromium 153, 박스의 SwiftShader = 소프트웨어 GPU, 각 10초 = 600 프레임)
| 창 | 스프라이트 | 평균 FPS | 20ms 넘는 프레임 | 렌더 CPU 평균 / 최대 |
|---|---|---|---|---|
| 1920×1080 | 2 | 60.0 | 0 | 1.89 / 3.4 ms |
| 1920×1080 | 42 | 59.9 | 1 (33 ms 한 번) | 2.22 / 7.0 ms |
| 1280×720 | 2 | 60.0 | 0 | 0.96 / 2.6 ms |
| 1280×720 | 42 | 60.0 | 0 | 1.16 / 3.6 ms |

메모리: 배경 1920×1080 디코드 ≈ 8.3 MB/화면 (지금 1280×720 ≈ 3.7 MB), 768×432 버퍼 1.3 MB, sharp-bilinear 중간 버퍼 2304×1296 ≈ 12 MB, 스프라이트 시트는 수십 KB. 디스크: 배경 JPG ≈ 0.75 MB/화면.
게임 엔진 전체(전투 · HUD · 몹) 안에서 잰 값은 아님 — 독립 페이지 값.

## 문제 · 한계 (솔직하게)
- 배경은 생성 해상도가 1280×720 → 1920×1080 으로 확대(Lanczos + 약한 샤픈). 1080p 에선 괜찮지만 1440p/4K 에선 조금 흐릿. 본 작업은 화면당 1920×1080 이상으로 그려야 함.
- 배경이 한 장짜리 그림이라 **가림(occlusion)이 없음**: 이 샘플에선 분수 · 가로등 · 나무 뒤로 지나가지 않게 경로를 잡았음. 본 작업에선 집 지붕 · 나무 · 가로등 · 분수 앞쪽 같은 소품을 따로 잘라 y 정렬해야 하고 충돌 데이터도 새로 만들어야 함.
- 오른쪽 상점 건물은 아주 약간 비스듬함 (생성 결과). 문 높이 ≈ 주인공 키 (조금 작음).
- 여성 NPC: 68px 에서 7.9 등신이면 머리가 약 9px → 얼굴은 눈 · 입 몇 픽셀 수준. 걷기 프레임은 정면(아래) 4장만, 다리 움직임이 작음. 장면에선 서 있는 프레임으로 배치.
- 주인공은 지금 게임과 같은 원본 시트를 새 파이프라인으로 56px 로 다시 줄인 것 (디자인 동일, 해상도 2배). 원본 걷기 시트가 이미 있어서 거의 자동.
- 768×432 는 1920×1080 에서 2.5배(비정수). sharp-bilinear 로 고르게 보이지만 픽셀 가장자리가 아주 약간 부드러움. 640×360 으로 하면 720p 2배 / 1080p 3배 / 1440p 4배 정수배가 되지만 캐릭터가 화면에서 약 20% 커 보임 — 결정 필요.
