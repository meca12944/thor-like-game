# 보고 체계 (알들 컴퍼니)

> 사장님 11-11 「보고 체계도 잘 만들어」. 일은 **한 흐름**으로 보여요.

## 상태 4단계

접수 → 진행 중 → 완료

막히면 **문제 있음**으로 빠져요.

| 상태 | 뜻 | 누가 바꾸나 | 어디에 적나 |
|---|---|---|---|
| 접수 | 사장님이 일을 보냄 | 프로그램이 보내는 순간 바로 | 사장님 PC의 `data/company-reports.json` (깃에 안 올라감) |
| 진행 중 | 팀장이 맡아서 하는 중 | 그록 팀장이 최종 보고 파일에 적음 | `office/data-public/reports.json` |
| 완료 | 검수까지 끝남 | 그록 팀장 | 같은 공개 파일 |
| 문제 있음 | 못 끝내거나, 그록 봇에게 전달이 안 됨 | 그록 팀장. 전달이 안 되면 프로그램이 로컬 접수 칸만 바꿈 | 공개 파일, 또는 로컬 접수 파일 |

화면 색 (움직임 없음): 완료는 초록, 진행 중은 회색, 문제 있음은 빨강, 접수는 파랑. 색 이름은 `var(--green)` `var(--muted)` `var(--red)` `var(--blue)` 라서, 테마 파일이 같은 이름을 쓰면 그대로 따라가요.

## 어디에 무엇이 있나

1. **그록 팀장 최종 보고** — `office/data-public/reports.json`
   - 그록이 PR(합치기 부탁)이나 커밋으로 올려요. main에 바로 올리지 않아요.
   - 이 저장소는 공개예요. 여기 적힌 글은 누구나 봐요.
2. **방금 접수** — 사장님 PC `data/company-reports.json`
   - 「회사 일 시키기」로 보내는 순간에 「접수」 한 줄이 생겨요.
   - 그록 봇에게 보내는 내용에 보고서 번호(`reportId`)를 함께 넣어요. 팀장은 그 번호를 그대로 최종 보고의 `id`에 써요.
3. **클로드 직원 보고** — 프로그램 안의 `state.reports`
   - 직원이 일을 마치면 지금처럼 여기에 쌓여요.
   - 보고 창은 **읽기만** 해요. 상태를 바꾸거나 글을 고치지 않아요.
   - 화면에 보일 때: 문제가 있으면 「문제 있음」, 사장님 확인이 필요하면 「진행 중」, 아니면 「완료」. 대상은 게임 필멸자.

보고 창(`GET /api/company/reports`)은 이 세 가지를 **한 목록**으로 모아 최신이 위로 오게 돌려줘요.
깃허브의 공개 파일을 먼저 읽고(몇 분 기억), 실패하면 PC 안의 `office/data-public/reports.json` 을 써요.

**같은 보고서 번호가 공개 파일에 있으면, 그 상태·요약·결과가 로컬 접수를 이깁니다.** 접수 줄과 완료 줄이 두 장으로 보이지 않아요.

## 한 줄에 들어갈 것

| 칸 | 내용 |
|---|---|
| id | 보고서 번호. 접수 때 생긴 번호를 최종 보고에도 그대로 |
| time | 한국 시간. 예: 2026-11-11 16:22 |
| target | 부서 또는 팀원 |
| command | 명령 한 줄 |
| lead | 검수한 팀장 (접수 때는 그 부서 담당 팀장) |
| status | 접수 / 진행 중 / 완료 / 문제 있음 |
| summary | 쉬운 말 1~3줄 |
| where | 결과물 주소 (http 또는 https) |
| source | 그록 또는 클로드 |

최종 보고(진행 중·완료·문제 있음을 공개 파일에 올릴 때)는 **요약 1~3줄**과 **결과 주소**가 필요해요. 접수만 결과 주소가 비어도 돼요.

## 절대 넣지 말 것

비밀, 열쇠, 비밀번호, 개인정보, 그록 봇 주소. 공개 파일과 이슈 글과 PR 글 모두 같아요.

게임 필멸자 말고 다른 부서의 정산·고객 내용은 공개 파일에 올리지 않아요. 그록 팀장끼리의 진행 보고(이 저장소에 있어도 되는 것)만 올려요.

## 화면

「🏢 회사 일 시키기」 칸 위 **📋 보고 창**.

- 한 줄: 접수 n · 진행 중 n · 완료 n · 문제 n (지금 고른 부서 기준)
- 버튼: 전체 / 부서 6개. 누르면 그 부서만 보여요. 움직이지 않아요.
